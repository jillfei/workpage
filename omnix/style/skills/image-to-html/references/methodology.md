# 图片 1:1 转 HTML 方法论

本文档定义「给定一张图片（UI 设计稿 / 网页截图），产出与之高度一致的单文件 HTML」的标准工作流。目标是 **视觉与结构的 1:1 还原**，而非「语义上差不多」。

适用图片类型（来自 skill 定位）：
- UI / 网页设计稿（Figma / PS 导出、线框图）
- 现有网页 / App 截图（想复刻成可编辑 HTML）

---

## 一、总体流程

```
1. 读取图片（Read 工具，多模态）→ 获得视觉全貌 + 逐字转录文字
2. 量化分析（scripts/analyze_image.py）→ 精确尺寸、主色板、色彩网格
3. 结构拆解 → 分区、栅格、间距、字体层级、组件清单
4. 生成单文件 HTML+CSS → 零依赖、双击即开
5. 还原度自检 → 逐项核对清单
6. present_files 预览 → 与用户迭代微调
```

---

## 二、步骤 1：读取图片（多模态）

- 使用 Read 工具直接读取用户提供的本地图片路径（支持 PNG / JPG / WebP 等）。
- 读取后，**逐字、逐块转录图片上的所有文字**（标题、导航、按钮、表单 label、表格内容、页脚）。1:1 还原要求文字内容准确，不可臆造或省略。
- 同时记录：
  - 整体画布尺寸观感（宽屏 / 移动端 / 卡片）
  - 顶部到尾部的分区顺序
  - 明显的视觉风格（扁平 / 拟物、圆角程度、阴影强弱、配色基调）

> 若用户未提供图片路径，先要求其提供，不要凭空生成。

---

## 三、步骤 2：量化分析（analyze_image.py）

运行分析脚本获取客观数据，避免凭肉眼估算尺寸与颜色：

```bash
# 使用 managed venv 中的 python（已装 Pillow）
<managed_venv>/Scripts/python.exe scripts/analyze_image.py <图片路径> --top 12 --grid 16
```

关键产出：
- **width × height**：作为 HTML 画布基准（固定宽度还原用）。
- **palette**：主色板 hex，直接用于 CSS 变量（背景、主色、文字、边框）。
- **color grid**：空间色彩分布，用于核对大区块位置（如顶部蓝条、底部深色 footer）。

辅助命令：
- 定点取色（核对某像素颜色）：`--points "120,40;900,60"`
- 区域裁剪导出（单独还原某组件时用）：`--crop x1,y1,x2,y2 --crop-out out.png`

> 当图片在模型视角下文字模糊或存在疑似 OCR 歧义时，用 `--points` 取关键文字区域的平均色，确认是主色还是辅助色。

---

## 四、步骤 3：结构拆解框架

把图片分解为以下维度，再动手写代码：

| 维度 | 关注点 |
|------|--------|
| 画布 | 固定宽度（如 1440 / 1200）还是移动端（375 / 390）；是否需要整体居中容器 |
| 分区 | 从上到下：导航 / Hero / 内容区 / 侧栏 / 页脚；各分区背景色（对照 color grid） |
| 栅格 | 列数、列间距（gutter）、内容最大宽度（max-width）、左右留白 |
| 间距 | 区块内外边距节奏（8 / 12 / 16 / 24 / 32 倍数） |
| 字体 | 字号层级（标题/正文/辅助）、字重、行高、字色（对照 palette） |
| 组件 | 按钮（主/次/幽灵）、输入框、卡片、标签、表格、图标、徽标、分页 |
| 圆角/阴影 | border-radius 取值、box-shadow 方向与模糊度 |
| 图片 | 照片/插画的位置与宽高比 → 用占位块（带正确比例 + 注释待替换） |

拆解后在脑中（或简短列出）形成组件树，再映射为 HTML 结构。

---

## 五、步骤 4：生成单文件 HTML+CSS

### 硬性规则（零依赖）
- 单个 `.html` 文件，CSS 写在 `<style>` 内（或 `<head>` 内联），**不引用任何外部 CSS/JS/CDN/字体文件**。
- 字体优先使用系统字体栈（见 css-patterns.md），确需特殊字体时以 `font-family` 声明 + 系统回退，不在文件里嵌外部 `@import`。
- 图标：能用 CSS 画的用 CSS，复杂图标用内联 `SVG`；不要引用外部图标库。
- 图片：用 `<div class="ph">` 占位（保持宽高比），并在注释中标注「此处替换为真实图：路径/尺寸」。

### 画布策略（1:1 关键）
- **固定宽度还原**：用 `.canvas { width: <img_width>px; margin: 0 auto; }` 包住整页，使桌面预览与源图 1:1。对超宽图加 `transform: scale()` 或外层 `overflow:auto` 便于查看。
- **响应式还原**（用户需要可适配时）：以源图尺寸为 desktop 基准，用 `max-width` + `media query` 给出移动端布局；默认仍先保证桌面 1:1。

### 颜色与单位
- 所有颜色用脚本给出的 hex，定义为 `:root` CSS 变量（如 `--c-primary:#1677FF`）。
- 间距、字号、圆角尽量用与源图一致的 px 值；节奏统一的地方用变量。

### 文本与可访问性
- 转录文字直接写入 HTML，保持原文（含标点、大小写）。
- 交互元素（按钮、链接）保留 `aria-label` / 语义标签（`<button>`、`<nav>`、`<a>`）。

---

## 六、步骤 5：还原度自检清单

生成后逐项核对（可对照源图在预览中叠加比较）：

- [ ] 画布宽高与源图一致（或等比缩放可控）
- [ ] 顶部→底部分区顺序、背景色与 color grid 吻合
- [ ] 所有可见文字已逐字还原，无遗漏/臆造
- [ ] 主色板已用上，无明显偏色
- [ ] 关键组件（按钮/输入框/卡片/表格）形态、圆角、阴影接近
- [ ] 字体层级（大小/字重/行高）层级关系正确
- [ ] 图标/图片以占位或内联形式存在，比例正确
- [ ] 单文件、零外部依赖，本地双击可正常渲染

---

## 七、步骤 6：预览与迭代

- 用 `present_files` 打开生成的 HTML，进入内置预览面板。
- 告诉用户「已按源图 1:1 还原，可对照查看；哪些细节需要微调（高度/布局/字段排列）」。
- 迭代时按用户反馈定位具体区块修改，**不要整体重写**；改完再次 `present_files`。

---

## 八、常见边界处理

- **渐变背景**：用 `linear-gradient` 取两端 hex（必要时 `--points` 取起止色）。
- **阴影/发光**：`box-shadow` 用 `0 2px 8px rgba(...)`，模糊度按视觉估；半透明色用 `rgba()`。
- **图表（柱状/折线/饼）**：用 CSS/SVG 近似还原形状与配色；数据标签按源图转录；精确数据可视化需求需告知用户此为静态还原。
- **照片区**：占位块保持宽高比，注释待替换；不要虚构照片内容。
- **深色模式 / 主题**：默认还原源图所见的主题；若源图含明暗双态，优先还原主态，并注明另一态待补充。
- **超长页面**：单文件内用正常文档流，避免人为截断；分页/标签等 UI 组件若用户需要交互，放在页面底部并以注释说明。
