一、概述

1.1 背景与问题

在 AI 智能体平台中，外部服务（地图、邮箱、即时通讯、数据库、知识库等）是扩展智能体工具能力的核心来源。用户需要把这些外部服务接入平台，让智能体在对话过程中能够调用它们完成实际任务。MCP（模型上下文协议）是当前业界通行的服务接入标准，本模块围绕 MCP 服务的接入与管理展开。

在没有统一管理能力之前，用户面临以下问题：

  • 接入门槛高：接入一个服务需要手工编写配置文件，格式复杂、容易出错，非技术用户几乎无法完成；
  • 缺少统一入口：已接入的服务散落各处，没有一个页面能集中查看"我到底接了哪些服务"；
  • 能力不透明：接入一个服务后，用户不知道它到底提供了哪些工具、每个工具能做什么，只能靠试；
  • 管理链路长：修改服务配置、移除不再使用的服务，操作入口分散，路径长且缺少防误操作保护。

因此，本模块要建设一个统一的 MCP 服务管理中心：让技术用户能通过表单快速接入自建服务，让非技术用户能从服务市场一键安装官方预置服务，所有服务在同一列表中集中呈现，并可随时查看详情、修改配置、安全卸载。

1.2 目标用户与典型场景

🔧 技术开发者

自行部署了服务端程序的技术用户，熟悉传输协议与服务地址等概念。他们需要把自建服务接入平台，并在服务端变更后快速更新配置。关注配置的灵活性与准确性。

🏢 业务用户

希望扩展智能体能力但没有技术背景的用户。他们不想理解协议与地址，只想"点一下就能用"，倾向于从服务市场直接安装钉钉、飞书、QQ邮箱等成熟服务。关注安装的便捷性。

👁️ 服务管理者

负责维护团队已接入服务的用户。他们需要定期盘点服务清单、了解每个服务的能力范围、下线不再使用的服务。关注管理效率与操作安全（防误删）。

典型场景

序号场景描述
1接入自建服务开发者在内网部署了一个联网搜索服务，通过"添加服务器"表单填写名称、协议、地址后完成接入，智能体即可使用该服务的搜索能力。
2一键安装市场服务业务用户想让智能体帮忙收发邮件，在服务市场找到 QQ 邮箱服务，点击安装按钮，几秒后即完成安装。
3评估服务能力用户在决定是否使用某个地图服务前，进入该服务的详情页，浏览它提供的全部工具及说明，判断是否满足出行规划需求。
4更新服务配置自建服务的部署地址发生变更，开发者打开编辑弹窗修改服务地址并保存，无需重新接入。
5下线冗余服务管理者盘点后发现某服务已无人使用，通过卸载操作（带二次确认）将其安全移除。

1.3 核心概念

概念定义
MCP 服务按照模型上下文协议对外提供能力的外部服务。一个服务通常打包了一组相关工具，例如地图服务包含路径规划、地点搜索等多个工具。
自定义 MCP由用户自行部署、通过表单填写配置接入平台的服务。用户对其拥有完整的编辑权（名称、协议、地址等均可修改），接入即视为已安装。
MCP 市场平台预置的官方服务货架。市场中的服务配置由平台维护，用户只需安装/卸载，不能修改其配置。
工具服务对外提供的最小能力单元，例如"骑行路径规划""关键词搜索地点"。智能体在对话中实际调用的就是工具。
传输协议平台与服务之间的通信方式，接入自定义服务时必须指定，当前支持三种：SSE、Stdio、Streamable HTTP。
安装状态标记某个服务当前是否可被智能体使用。市场服务存在"未安装 / 已安装"两种状态；自定义服务接入后恒为已安装。

1.4 用户故事

作为 技术开发者，我希望通过填写服务名称、传输协议、服务地址等信息完成自建服务的接入，以便把我部署的服务快速变成智能体可用的工具能力。
作为 业务用户，我希望在服务市场中一键安装预置服务，以便不了解任何技术细节也能扩展智能体的能力。
作为 用户，我希望进入任意服务的详情页，看到它的介绍和完整工具清单，以便在使用前评估该服务能帮我做什么。
作为 技术开发者，我希望随时修改已接入自定义服务的配置并保存，以便在服务端地址或参数变更后保持服务可用。
作为 服务管理者，我希望卸载服务时有明确的二次确认，以便安全下线服务，避免误操作导致智能体能力缺失。

1.5 非目标

本期不做以下内容：
  • 不提供服务的在线调试与工具试运行能力（仅管理接入配置，不提供运行时验证）；
  • 不提供服务市场的搜索、分类、排序能力（市场为预置固定货架）；
  • 不提供服务配置的版本管理与回滚；
  • 不提供服务级别的权限管控（不区分不同用户的可见与可用范围）；
  • 不提供服务的调用日志、调用量统计与健康监控；
  • 不涉及服务端程序本身的开发、部署与托管。

二、功能架构与流程图

2.1 系统架构图

模块由两个页面构成：服务列表页（统一入口，承载浏览、添加、编辑、安装、卸载）与服务详情页（承载单个服务的介绍、工具清单与安装/卸载操作）。点击列表中的服务卡片进入对应详情页。

2.2 业务流程图

三条核心业务流程：自定义服务的接入与维护、市场服务的安装与卸载、服务详情的查看。

三、详细设计

本模块共两个页面：3.1 服务列表页（浏览与全部管理操作的入口）和3.2 服务详情页（单个服务的能力展示与安装/卸载）。每个页面按"功能描述 → 显示数据说明 → 操作字段说明 → 操作说明"四部分展开。

🔹 3.1 服务列表页

功能描述

服务列表页是模块首页，集中呈现当前平台已接入及可安装的全部 MCP 服务。页面按来源分为两个分组：自定义 MCP（用户自行接入的服务）与 MCP 市场（平台预置的可安装服务）。每个服务以卡片形式展示图标、名称与描述；卡片右侧的操作区域随服务来源与安装状态变化：自定义服务卡片右上角悬浮显示三个点菜单（点击下拉显示"编辑"和"卸载"），同时右侧提供启禁用开关；市场服务未安装时显示"安装"入口、已安装后在悬停时显示"卸载"入口。页面右上角提供"添加服务器"入口用于接入自定义服务。点击卡片本身（非按钮区域）进入该服务的详情页。

显示数据说明

字段显示规则来源及说明
分组标题 页面自上而下分为「自定义MCP」「MCP市场」两个分组，各自带分组标题；分组内服务以卡片纵向排列 系统固定分组；服务归属由其来源属性决定，不可跨组移动
服务图标 卡片左侧展示 40×40 圆角图标。市场服务展示品牌色底 + 品牌首字（如钉钉为蓝底"钉"、飞书为青底"飞"、QQ邮箱为黄底"Q"）；自定义服务展示浅灰底的默认线条图标 市场服务的品牌图标由平台预置；自定义服务当前统一使用默认图标
服务名称 卡片主标题，单行展示，深色加粗 自定义服务来自用户接入时填写的名称，编辑保存后实时更新；市场服务为平台预置名称，不可修改
服务描述 展示于名称下方，浅灰小字，最多两行，超出部分以省略号截断 自定义服务来自用户填写的描述；市场服务为平台预置文案
更多操作菜单 仅自定义服务卡片右上角显示三个点图标按钮，默认隐藏，鼠标悬停卡片时浮现；点击后展开下拉菜单，包含「编辑」和「卸载」两个选项 由服务来源派生：来源为自定义时悬停显示；点击菜单项触发对应操作
启禁用开关 仅自定义服务卡片右侧显示开关控件，默认开启状态（绿色）；点击可切换启用/禁用状态，切换后顶部弹出轻提示 由服务来源派生：来源为自定义时显示；开关状态变化时提示「已启用 ×××」或「已禁用 ×××」
安装入口 仅"未安装"的市场服务卡片右侧显示"＋"按钮；安装进行中该位置替换为加载动画 由服务来源与安装状态派生；安装完成后该按钮消失
卸载入口 仅"已安装"的市场服务卡片显示，位于卡片右上角，默认隐藏，鼠标悬停卡片时浮现，悬停按钮时变红色警示 由安装状态派生；点击后进入卸载确认流程
操作结果提示 接入、保存、安装、卸载成功后，页面顶部居中弹出深色轻提示（如「MCP 添加成功」「保存成功」「已卸载 ×××」），2.5 秒后自动消失 系统根据操作结果生成，无需用户关闭
💡 市场服务品牌色约定：钉钉—蓝、飞书—青绿、SQL查询助手—深蓝、ima知识库—黑、QQ邮箱—黄。品牌视觉在列表页与详情页保持一致，帮助用户快速识别服务。

操作字段说明（添加 / 编辑服务弹窗）

接入自定义服务与编辑已接入服务共用同一套表单字段。编辑弹窗打开时自动回填该服务的当前配置。

字段类型必填说明
服务器名称 单行文本 是 服务的展示名称，输入框内置提示「请输入服务器名称」；提交时校验非空，为空则轻提示「请输入服务器名称」且不提交
传输协议 单选下拉 是 三个选项：SSE、Stdio、Streamable HTTP；默认为占位项「选择传输协议」；提交时校验已选，未选则轻提示「请选择传输协议」
描述 多行文本 是 服务功能说明，内置提示「请输入MCP服务描述」；输入区支持纵向拉伸；提交时校验非空，为空则轻提示「请输入描述」
服务地址 单行文本 是 服务的访问地址，内置提示含地址示例；提交时仅校验非空，为空则轻提示「请输入服务地址」；本期不做地址格式与连通性校验
请求头 单行文本 否 用于携带鉴权等自定义请求头，按约定的键值对格式填写（输入框内置格式示例）；本期前端不校验格式，由服务端校验并反馈
💡 编辑弹窗与添加弹窗字段完全一致，差异点：① 标题为「编辑MCP」；② 打开时回填当前配置；③ 主操作按钮为「保存」，按钮靠右对齐；④ 卸载操作已移至卡片右上角三个点菜单中，编辑弹窗内不再提供卸载入口。

操作说明

操作前提效果边界与例外
添加服务器 无 点击页面右上角「添加服务器」，弹出接入表单弹窗，字段均为空 弹窗打开期间页面背景加遮罩；点击关闭按钮、取消按钮、遮罩空白处或按下退出键均可放弃并关闭弹窗，已填内容不保留
提交接入 已打开添加弹窗 点击「添加MCP」提交；校验通过后弹窗关闭，轻提示「MCP 添加成功」，新服务出现在自定义分组 任一必填项缺失时按"名称 → 协议 → 描述 → 地址"顺序提示第一个缺失项，弹窗不关闭、已填内容保留
编辑服务 目标为自定义服务 悬停卡片显示右上角三个点菜单按钮，点击展开下拉菜单，选择「编辑」，弹出编辑弹窗并回填该服务当前配置 点击菜单按钮不触发卡片跳转详情页（两个点击行为互相隔离）；市场服务无此菜单入口
保存编辑 已打开编辑弹窗 校验通过后关闭弹窗，轻提示「保存成功」，卡片上的名称与描述即时更新 校验规则与提交接入一致；校验失败不关闭弹窗；取消或关闭弹窗则放弃全部修改
卸载自定义服务 目标为自定义服务 悬停卡片显示右上角三个点菜单按钮，点击展开下拉菜单，选择「卸载」，弹出确认弹窗（标题「卸载 MCP」，副标题「此操作不可撤销」，正文「确定要卸载 ××× 吗？」）；点击「确认卸载」后服务卡片从列表移除，轻提示「已卸载 ×××」 点击「取消」、关闭按钮或遮罩空白处均视为放弃卸载；自定义服务卸载后彻底移除，不提供"未安装"占位
启禁用自定义服务 目标为自定义服务 点击卡片右侧的启禁用开关，切换服务的启用/禁用状态；切换后顶部弹出轻提示「已启用 ×××」或「已禁用 ×××」 开关状态变化不影响服务配置，仅标记服务当前是否可被智能体调用；市场服务无此开关
安装市场服务 目标为市场服务且未安装 点击卡片右侧「＋」，按钮替换为加载动画（约 1.2 秒），完成后轻提示「添加×××成功」，卡片进入已安装状态（悬停显示卸载入口） 加载期间原按钮已被替换，天然防止重复提交；点击「＋」不触发卡片跳转
卸载市场服务 目标为市场服务且已安装 悬停卡片显示右上角卸载按钮，点击后弹出确认弹窗（标题「卸载 MCP」，副标题「此操作不可撤销」，正文「确定要卸载 ××× 吗？」）；点击「确认卸载」后卡片恢复未安装状态（重新出现「＋」），轻提示「已卸载 ×××」 点击「取消」、关闭按钮或遮罩空白处均视为放弃卸载；市场服务卸载后保留在市场分组中，可随时重新安装（与自定义服务"卸载即移除"不同）
进入详情页 无 点击卡片非按钮区域，跳转到该服务的详情页，并携带服务名称、图标、来源与安装状态信息 点击卡片上的编辑、安装、卸载按钮不触发跳转；自定义服务进入详情页时安装状态恒为已安装
快捷关闭弹窗 任一弹窗处于打开状态 按下退出键关闭当前打开的弹窗（添加 / 编辑 / 卸载确认） 关闭即视为放弃当前操作；卸载确认弹窗被关闭时不执行卸载

🔹 3.2 服务详情页

功能描述

服务详情页用于展示单个 MCP 服务的完整信息，帮助用户在使用前评估其能力。页面自上而下包含：返回导航、服务头部（图标、名称、来源标签、操作区）、服务介绍（一段概述 + 详细说明）以及工具清单（该服务提供的全部工具及各自的功能说明）。头部操作区根据服务来源与安装状态呈现三种互斥形态：自定义服务不展示任何操作；未安装的市场服务展示「添加MCP」按钮；已安装的市场服务展示「卸载」按钮。页面进入时所需的服务基础信息（名称、图标、来源、安装状态）由列表页跳转时传入。

显示数据说明

字段显示规则来源及说明
返回导航 页面顶部左侧展示「← MCP」，点击返回服务列表页 系统固定导航元素
服务图标 头部左侧 40×40 圆角图标；市场服务展示与列表页一致的品牌色底 + 品牌首字；自定义服务展示浅灰底默认图标；无法识别时展示系统缺省图标 由列表页传入的图标标识与来源共同决定，与列表页视觉保持一致
服务名称 头部主标题，大号加粗；同时同步到浏览器标签页标题（格式：服务名 - MCP） 由列表页传入；未传入时展示系统默认名称
来源标签 名称下方的小型胶囊标签：自定义服务为紫色系「自定义MCP」，市场服务为青色系「MCP市场」 由来源信息派生；来源缺失时整个标签隐藏，不展示空标签
服务概述 内容区顶部的一段总览文字，概括服务的整体能力范围 服务的介绍内容，随服务预置
服务详细介绍 「服务介绍」小节，含小节标题与多段说明文字，介绍服务的功能构成与典型使用场景 服务的介绍内容，支持多段落展示
工具数量 「工具列表」小节标题旁展示该服务的工具总数 由工具清单条目数派生
工具清单 纵向列表，每项包含工具图标、工具名称（蓝色强调）与功能描述（灰色小字）；清单首项以浅灰底色卡片高亮，其余项以分隔线区隔 服务对外声明的工具集合；首项高亮用于突出该服务的代表性能力
头部操作区 三种互斥形态：① 自定义服务——整体隐藏；② 市场服务未安装——展示「添加MCP」按钮；③ 市场服务已安装——展示红色系「卸载」按钮。添加进行中按钮替换为加载动画 由来源与安装状态共同派生；安装状态缺失时按未安装处理
操作结果提示 添加、卸载成功后顶部居中弹出深色轻提示，2.5 秒后自动消失 系统根据操作结果生成

字段类型必填说明
服务名称 文本 否 用于渲染页面主标题与浏览器标签页标题；缺失时展示系统默认名称
图标标识 枚举 否 用于匹配品牌图标或默认图标；无法匹配时展示系统缺省图标

安装状态 布尔 否 仅对市场服务生效：已安装则直接展示「卸载」按钮，未安装或缺失则展示「添加MCP」按钮

操作说明

操作前提效果边界与例外
返回列表 无 点击顶部「← MCP」返回服务列表页 本页内已完成的添加/卸载操作结果，返回后应与列表页状态保持一致
添加服务 市场服务且当前未安装 点击「添加MCP」，按钮隐藏并显示加载动画（约 0.8 秒）；完成后轻提示「添加×××成功」，操作区切换为「卸载」按钮 加载期间按钮已隐藏，无法重复点击；详情页添加时长（约 0.8 秒）短于列表页安装（约 1.2 秒），体验上更轻快
发起卸载 市场服务且当前已安装 点击「卸载」按钮，弹出确认弹窗：标题「卸载 MCP」、副标题「此操作不可撤销」、正文「确定要卸载 ××× 吗？」 弹窗打开期间背景加遮罩；同一时间仅存在一个确认弹窗
确认卸载 卸载确认弹窗已打开 点击「确认卸载」后弹窗关闭，轻提示「已卸载 ×××」，操作区恢复为「添加MCP」按钮，用户可再次添加 卸载后服务回到未安装状态而非从平台消失；恢复的添加按钮功能完整，可立即再次发起添加
放弃卸载 卸载确认弹窗已打开 点击「取消」、右上角关闭按钮或弹窗外遮罩区域，关闭弹窗且不执行卸载 任何一种关闭方式均不改变服务当前状态
💡 一致性要求：详情页与列表页对同一服务的品牌视觉（图标、配色）、来源标签样式、轻提示文案风格必须保持一致；卸载确认弹窗的文案与交互在两个页面完全统一，降低用户学习成本。
