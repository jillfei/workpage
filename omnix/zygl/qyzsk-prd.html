一、概述

1.1 角色定义

知识库内共设四类角色，权限由高到低依次为：

角色定义说明
所有者 知识库的唯一负责人 创建该知识库的用户，或经转让后承接的用户。可随时将知识库转让给管理员或编辑者，转让后原所有者变为管理员。
管理员 协助所有者管理知识库 可管理成员与角色、维护内容与配置，但不能删除知识库或转让所有权。
编辑者 内容维护者 可维护文件、Wiki 与检索内容，可修改知识库配置，但不能管理成员。
只读 仅可查看与检索 可浏览文件、Wiki、分块与操作日志，不能做任何写操作。

二、权限设计

2.1 权限矩阵

下表定义四类角色在知识库各项能力上的准入边界。✓ 表示具备该能力，— 表示不具备。

能力 所有者 管理员 编辑者 只读
查看 / 检索知识库内容✓✓✓✓
编辑知识库文件 / Wiki✓✓✓—
上传 / 删除文档✓✓✓—
修改知识库配置✓✓✓—
管理成员与角色✓✓——
删除知识库 / 转让所有者✓———
⚠️
权限收缩原则：角色之间是包含关系，高权限角色自动具备低权限角色的全部能力。任何写操作在执行前都要二次校验，不能只依赖界面按钮的显隐。

2.2 界面元素可见性

管理端自身的权限由菜单权限与角色权限两套配置构成（配置入口：企业管理 → 菜单管理 / 角色管理），即 2.3 中的系统权限维度。

管理端中知识库相关界面元素（按钮、菜单、入口等）的显隐，先继承客户端的知识库角色权限判定结果（见客户端《企业知识库 · 功能说明》「各角色可操作按钮一览」），再与管理端自身的菜单 / 角色权限取并集——客户端角色或管理端权限任意一侧放行，该元素即显示；两侧均不具备时才隐藏。

同一界面元素对应多项能力时，同样取并集：具备其中任意一项即显示。

ℹ️
示例：某成员在知识库 A 中为「只读」角色（客户端不具备「上传 / 删除文档」能力），但其管理端角色被授予了知识库管理权限，则管理端中该知识库的「添加文档」入口仍对其显示。

2.3 系统权限与知识库权限

系统中的权限由两套独立的权限体系共同决定，最终生效的权限是二者的并集：

权限来源作用范围说明
系统权限
（平台级）		 整个管理端 由账号在企业管理中分配的系统角色决定，例如「管理员」「普通成员」。决定该用户能否进入管理端、能否看到企业知识库菜单、能否使用容量配额等平台级功能。
知识库权限
（资源级）		 单个知识库 由用户在该知识库内的角色决定，即 2.1 权限矩阵中的所有者 / 管理员 / 编辑者 / 只读。

最终权限 = 系统权限 ∪ 知识库权限

判定顺序：

  1. 先校验 系统权限：账号无管理端访问权限 → 无法进入管理端（此维度为门槛条件，不参与并集；客户端访问不受影响）；
  2. 再取 知识库权限：取用户在该知识库中的角色（所有者 / 管理员 / 编辑者 / 只读；非成员按只读处理）；
  3. 两者取并集：系统权限或知识库权限任一侧允许的操作即可执行，管理端权限可突破知识库内的角色边界，用于企业级管理与兜底。
示例
用户 A 的系统角色具备知识库管理权限（系统权限允许删除知识库），但在知识库 X 中只是「编辑者」（知识库权限不允许删除）。
→ 并集结果：可以删除知识库 X。管理端权限可突破知识库内的角色边界；如不希望系统角色拥有该能力，不要在角色管理中授予对应权限。

取并集的典型场景

系统权限知识库权限最终结果说明
无管理端访问权限 任意角色 无法进入管理端 管理端访问权限是门槛条件，不满足时知识库角色在管理端无意义；客户端访问不受影响。
仅基础访问权限（无知识库管理授权） 只读 只读 管理端未授予知识库能力时，退化为知识库内角色，仅能浏览。
有知识库管理权限 只读 系统权限生效 可执行系统角色允许的知识库操作（如编辑、删除），不受库内「只读」限制。
仅基础访问权限 编辑者 编辑者 可维护内容与配置，但不能管理成员、不能删除知识库。
仅基础访问权限 管理员 管理员 可管理成员与内容，但不能删除知识库或转让所有权。
仅基础访问权限 所有者 所有者 知识库内的全部权限。
有知识库管理权限 所有者 两侧能力叠加 知识库内全部权限 + 系统角色授予的管理端能力。

边界情况

场景判定结果产品行为
用户不是知识库成员 知识库权限按「只读」 与系统权限取并集：默认仅可浏览内容，角色标签显示「只读」；若系统角色被授予知识库管理能力，则对应入口正常显示，可用于无主知识库接管等场景。
转让所有者 原所有者 → 管理员 新所有者承接全部知识库权限；原所有者降级为管理员，仍在成员列表中。系统权限不受影响。
只读用户访问 Wiki 页面 仅浏览 页面正文与参考来源可读，版本历史 / 编辑 / 移动 / 重命名 / 删除按钮全部隐藏。
只读用户查看文件分块 仅浏览 可展开 / 收起分块阅读，辅助召回问题、编辑分块、查看父块、启用开关均隐藏。

三、操作日志设计

3.1 日志字段

知识库详情页的「操作日志」页签按时间倒序展示该知识库的全部操作记录，字段定义如下：

字段类型说明
操作时间时间精确到分钟，格式 YYYY-MM-DD HH:mm，按时间倒序排列。
操作人用户触发该操作的用户，展示头像 + 姓名。
分类枚举操作所属的功能域，共 7 类：知识库 / 编辑知识库 / 文件 / 分块 / 文件夹 / 调整成员权限 / Wiki。
操作枚举具体动作，如「上传文档」「删除 Wiki 页面」。
对象 / 说明文本操作的具体对象与变更明细，例如「删除文件夹『竞品调研』（含 2 个文件）」。
来源枚举操作发起端：管理端 / 客户端。
