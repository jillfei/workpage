以下为调整后的方案：**平台统一处理意见反馈；处理完成后由平台更新结果并通知用户，用户仅可查看处理进度与结果，不设置“已解决 / 未解决”确认，也不支持基于原反馈重复提交。**

# 意见反馈功能需求（调整版）

## 一、业务闭环

**用户提交反馈 → 平台受理与处理 → 平台更新处理结果 → 通知用户查看 → 反馈归档。**

### 调整原则
1. 平台拥有反馈状态流转和关闭权限。  
2. 用户可查看本人反馈记录、当前状态、平台处理说明及历史进展。  
3. 不提供用户“已解决”“未解决”“重新打开”“补充后再次流转”等确认操作。  
4. 如用户有新的问题或建议，可通过“提交意见反馈”创建一条新的独立反馈。  
5. 不在客户端展示内部处理人、内部备注、技术排查过程、优先级及内部工单编号。

# 二、状态设计

## 2.1 客户端可见状态

| 状态 | 状态说明 | 是否由平台操作 |
|---|---|---|
| 已收到 | 平台已收到反馈，等待受理。 | 是 |
| 处理中 | 平台正在核实、评估或处理。 | 是 |
| 已处理 | 平台已完成处理，并给出处理结果或说明。 | 是 |
| 暂不支持 | 平台评估后暂不支持该建议或需求。 | 是 |
| 已关闭 | 反馈因重复、无效、信息不足或无法复现等原因关闭。 | 是 |

> “已处理”是终态之一，用户不需要确认是否解决。  
> “暂不支持”“已关闭”均需展示平台给出的说明。

## 2.2 管理端内部状态

| 内部状态 | 客户端展示状态 | 说明 |
|---|---|---|
| 待受理 | 已收到 | 用户提交后的默认状态。 |
| 已受理 | 处理中 | 工作人员已接收并开始跟进。 |
| 处理中 | 处理中 | 正在分析、处理或协调相关团队。 |
| 待发布结果 | 处理中 | 已形成内部处理结论，待确认后对用户发布。 |
| 已处理 | 已处理 | 已完成处理并已向用户说明结果。 |
| 暂不支持 | 暂不支持 | 当前不支持或暂不纳入计划。 |
| 已关闭 | 已关闭 | 重复、无效、信息不足、无法复现等。 |

# 三、管理端需求

## 3.1 反馈管理列表

### 3.1.1 功能说明
后台提供统一的意见反馈管理列表，用于工作人员查看、筛选、分派、处理、跟进和通知用户。

### 3.1.2 列表字段

| 字段 | 说明 |
|---|---|
| 反馈编号 | 系统自动生成的唯一编号。 |
| 反馈类型 | 例如功能建议、产品问题、体验建议、账号问题、其他。 |
| 反馈标题/内容摘要 | 展示标题或反馈内容摘要。 |
| 提交用户 | 用户昵称、用户 ID 等，敏感信息按权限脱敏。 |
| 来源端 | 如 iOS、Android、Web、PC 客户端。 |
| 当前状态 | 展示内部处理状态及客户端展示状态。 |
| 优先级 | 低、普通、高、紧急。 |
| 当前处理人 | 当前负责人员。 |
| 提交时间 | 用户提交时间。 |
| 最近更新时间 | 最近一次处理、回复或状态更新的时间。 |
| 跟进时间 | 下一次计划跟进时间。 |
| 超时状态 | 正常、即将超时、已超时。 |
| 通知状态 | 是否已向用户发送处理结果或状态通知。 |

### 3.1.3 检索与筛选
支持按以下条件筛选、搜索：

- 反馈编号；
- 用户 ID、昵称、联系方式等用户标识；
- 反馈类型；
- 来源端；
- 当前状态；
- 优先级；
- 处理人；
- 提交时间范围；
- 是否有附件；
- 是否超时；
- 是否已通知用户；
- 是否为重复反馈或无效反馈。

支持通过关键词搜索反馈标题、反馈正文及反馈编号。

### 3.1.4 列表操作
支持以下操作：

- 查看反馈详情；
- 受理反馈；
- 分派、转交处理人；
- 修改优先级；
- 更新处理状态；
- 填写处理结果；
- 创建跟进事项；
- 通知用户；
- 标记重复、无效或重点反馈；
- 批量更新状态；
- 批量导出反馈数据。

---

## 3.2 反馈详情

### 3.2.1 基础信息
详情页展示：

- 反馈编号；
- 反馈类型；
- 用户反馈标题及完整内容；
- 提交时间；
- 提交用户信息；
- 来源端、应用版本、设备信息、系统版本、网络环境等上下文信息；
- 用户上传的图片、视频、日志等附件；
- 当前状态、优先级、处理人；
- 当前跟进时间及超时情况。

### 3.2.2 处理信息
后台详情页展示并支持维护：

- 当前处理状态；
- 处理人、协同处理人；
- 内部备注；
- 处理结论；
- 对用户可见的处理说明；
- 关联的需求、缺陷、工单或版本信息；
- 是否需要通知用户；
- 通知内容及发送记录；
- 状态流转与操作日志。

### 3.2.3 历史记录
系统应按时间顺序记录以下内容：

- 反馈创建记录；
- 状态变更记录；
- 分派、转交记录；
- 跟进记录；
- 内部备注；
- 用户可见回复；
- 通知发送记录；
- 关联需求、缺陷或版本信息；
- 关闭、暂不支持或已处理的原因。

其中，**内部备注、处理人、优先级、关联工单等仅后台可见**。

---

## 3.3 受理、分派与处理

### 3.3.1 受理
工作人员可将“待受理”的反馈更新为“已受理”或“处理中”。

受理时可填写：

- 处理人；
- 优先级；
- 初步判断；
- 计划跟进时间；
- 内部备注。

### 3.3.2 分派与转交
支持将反馈分派给客服、产品、研发、运营等角色或团队。

分派、转交时需记录：

- 原处理人；
- 新处理人；
- 分派原因；
- 操作人；
- 操作时间；
- 是否需要同步通知用户。

默认情况下，内部转交**不通知用户**。

### 3.3.3 处理结果
当反馈完成处理时，工作人员需选择处理结论：

- 已处理；
- 暂不支持；
- 已关闭。

并填写：

- 内部处理结论；
- 对用户可见的处理说明；
- 可选：关联版本号、上线时间或替代方案；
- 是否立即通知用户。

### 3.3.4 必填规则
- 更新为“已处理”时，必须填写用户可见的处理结果说明。  
- 更新为“暂不支持”时，必须填写暂不支持原因或替代建议。  
- 更新为“已关闭”时，必须填写关闭原因。  
- 处理说明发布后不可直接删除；如需修改，应保留修改记录。  

---

## 3.4 跟进与时效提醒

### 3.4.1 跟进事项
处理人可创建跟进事项，包括：

- 下次跟进时间；
- 跟进内容；
- 跟进对象；
- 跟进结果；
- 是否需要通知用户。

到达跟进时间时，系统向处理人发送待办提醒。

### 3.4.2 超时规则
可按反馈类型和优先级设置处理时限，例如：

| 类型/优先级 | 首次受理时限 | 建议处理时限 |
|---|---:|---:|
| 普通建议 | 3 个工作日 | 视评估结果确定 |
| 一般产品问题 | 1 个工作日 | 3 个工作日 |
| 高优先级问题 | 4 小时 | 1 个工作日 |
| 紧急问题 | 即时 | 持续跟进至形成结果 |

系统应对即将超时、已超时的反馈进行标识，并向处理人或负责人发送提醒。

## 3.5 用户通知

### 3.5.1 通知触发场景

| 场景 | 是否通知用户 |
|---|---|
| 用户提交反馈成功 | 自动通知 |
| 平台开始处理 | 可配置，默认不通知 |
| 平台发布处理说明 | 自动通知 |
| 状态更新为已处理 | 自动通知 |
| 状态更新为暂不支持 | 自动通知 |
| 状态更新为已关闭 | 自动通知 |
| 内部转交处理人 | 不通知 |
| 内部更新备注或关联工单 | 不通知 |

### 3.5.2 通知内容
通知应包含：

- 反馈标题或编号；
- 当前处理状态；
- 处理结果摘要；
- 更新时间；
- 查看详情入口。

示例：

> 您提交的反馈“登录页面加载异常”已有处理结果，请前往“我的反馈”查看详情。

### 3.5.3 通知渠道
至少支持站内消息；如产品已有能力，可扩展 App Push、短信或邮件。

### 3.6.1 统计指标
建议提供：

- 反馈编号；
- 反馈类型；
- 用户信息（按权限脱敏）；
- 反馈内容；
- 当前状态；
- 优先级；
- 处理人；
- 提交时间；
- 最近更新时间；
- 处理结论；
- 用户可见处理说明；
- 通知状态。

# 四、客户端需求

## 4.1 我的反馈入口

### 4.1.1 入口位置
在“我的”“设置”或“帮助与反馈”模块提供“我的反馈”入口。

### 4.1.2 使用范围
“我的反馈”用于查看当前登录账号历史提交的全部意见反馈及平台处理结果。

未登录用户点击时，应引导登录后查看。

---

## 4.2 我的反馈列表

### 4.2.1 列表字段
每条反馈展示：

- 反馈类型；
- 反馈标题或内容摘要；
- 当前状态；
- 平台最新处理说明摘要；
- 提交时间或最近更新时间；
- 是否有新处理结果标识。

### 4.2.2 列表规则
- 默认按最近更新时间倒序排列；
- 支持按状态筛选：全部、已收到、处理中、已处理、暂不支持、已关闭；
- 支持下拉刷新和分页加载；
- 用户仅可查看本人账号提交的反馈；
- 无反馈记录时展示空状态，并提供“去提交反馈”入口。

### 4.2.3 新结果标识
当平台发布新的处理说明、更新处理状态或发送通知后，列表中应展示“新消息”或“有更新”标识；用户进入详情页后取消标识。

## 4.3 反馈详情

### 4.3.1 展示内容
详情页应展示：

- 反馈编号；
- 反馈类型；
- 用户提交的反馈内容；
- 提交时间；
- 用户提交的附件；
- 当前状态；
- 状态说明；
- 平台处理结果或回复；
- 状态变更记录；
- 最近更新时间。

### 4.3.2 状态说明示例

| 状态 | 客户端文案示例 |
|---|---|
| 已收到 | 平台已收到您的反馈，将尽快处理。 |
| 处理中 | 平台正在核实和处理，请耐心等待。 |
| 已处理 | 平台已完成处理，详情请查看处理说明。 |
| 暂不支持 | 当前暂无法支持该建议，感谢您的反馈。 |
| 已关闭 | 该反馈已关闭，详情请查看处理说明。 |

### 4.3.3 处理结果展示
当平台处理完成后，详情页重点展示：

- 处理结论；
- 平台回复/说明；
- 处理完成时间；
- 若适用，展示版本更新信息、操作建议或替代方案。

例如：

> **处理结果：已处理**  
> 该问题已在 V3.2.1 版本中修复，请升级至最新版本后使用。

## 4.4 客户端操作限制

客户端不提供以下操作：

- 不提供“已解决”“未解决”确认按钮；
- 不提供基于原反馈的“重新打开”功能；
- 不提供用户侧状态修改能力；
- 不提供用户侧处理人催办、转交能力；
- 不展示内部备注、内部负责人、优先级、技术排查记录或内部工单信息。

如用户需要反馈新的问题，可返回意见反馈入口，提交一条新的独立反馈。

---

## 4.5 客户端通知

用户在以下场景收到站内消息或推送：

- 提交反馈成功；
- 平台发布处理说明；
- 反馈状态更新为“已处理”；
- 反馈状态更新为“暂不支持”；
- 反馈状态更新为“已关闭”。

用户点击通知后，应直接进入对应反馈详情页。

# 五、关键业务规则

1. 用户只能查看本人账号提交的反馈记录。  
2. 用户提交反馈后，平台统一负责受理、分派、跟进、处理和关闭。  
3. 客户端状态仅由平台变更，用户无权更改。  
4. 反馈完成处理后，平台必须发布用户可见的处理说明。  
5. 状态变更为“已处理”“暂不支持”或“已关闭”时，应自动通知用户。  
6. 平台内部处理记录需完整留痕，包括操作人、操作时间、状态变更和处理说明。  
7. 用户不可对原反馈提交“已解决/未解决”结果，也不可基于原反馈发起重新处理。  
8. 新问题、后续意见或再次出现的问题，应由用户提交新的独立反馈。  
9. 重复反馈可由后台关联、合并或标记重复处理，但每位用户仍可在客户端看到本人提交记录及对应处理结论。  
10. 涉及账号、支付、安全、隐私等敏感反馈时，应限制后台查看范围，并在客户端避免展示敏感处理细节。

# 六、验收标准

## 管理端
- 可按用户、类型、状态、处理人、优先级、时间等条件检索反馈。  
- 可查看反馈内容、附件、操作记录和处理历史。  
- 可受理、分派、转交、跟进和更新反馈状态。  
- 更新为“已处理”“暂不支持”“已关闭”时，系统校验必须填写用户可见说明。  
- 平台处理完成或关闭反馈后，系统能够向用户发送通知。  
- 内部转交、内部备注不会展示给用户或默认通知用户。  
- 所有处理动作、状态变更和通知记录均可追溯。  

## 客户端
- 用户可查看本人历史提交的反馈列表。  
- 列表展示反馈摘要、当前状态、最近更新时间及处理结果更新标识。  
- 用户可进入详情查看反馈原文、附件、状态和平台处理说明。  
- 平台处理后，用户可在详情中查看明确的处理结果。  
- 用户无法在客户端确认“已解决/未解决”、修改状态或重新打开原反馈。  
- 用户收到通知后可跳转至对应反馈详情。
