通知管理模块

统一收口 · 全员触达 · 可查可溯 —— 产品需求文档 v1.0

文档版本修改日期修改人修改说明
v1.0 2026-11-06 产品 通知管理模块首版：提供系统通知的集中查看、条件检索与全员通知创建能力，覆盖通知列表、筛选检索、分页浏览、创建通知、通知详情与全局反馈提示。

一、概述

1.1 背景说明

企业内部的系统消息长期处于"多头产生、无人归口"的状态。系统运行过程中会自动产生大量业务消息——版本上线、维护停机、任务指派、审批结果、安全告警、报表生成等；同时行政、人事、运营等部门也需要主动发布放假安排、培训开课、网络升级等管理类通知。这些消息分散在各自的业务模块中，缺乏统一的沉淀与查看入口。

  • 消息产生方多，查看方无统一入口：系统自动产生的消息与管理员手动发布的消息混在各业务模块，接收人需要逐个模块翻找，容易漏看关键通知。
  • 管理员缺少发布工具：需要向全体员工同步一条管理通知时，只能依赖邮件或即时通讯群发，无法在系统内留痕，事后也无法确认发布过什么、何时发布。
  • 历史通知不可追溯：通知发出后没有集中归档，无法按来源、状态检索，也无法回看某条通知的完整内容与发布信息，出现争议时无据可查。
  • 通知类型不透明：使用者并不清楚系统究竟会在哪些场景下自动推送通知，缺少一份可自查的清单说明。

为此，需要在系统管理下建设通知管理模块：把系统自动产生与管理员手动发布的通知统一归集到一个列表中，提供检索、筛选与分页浏览能力；同时提供标准化的通知创建入口，让管理员能够以统一的格式向全员发布通知，并保证每条通知的标题、内容、来源、接收范围、发送时间与创建人都可查可溯。

1.2 需求描述

本期交付通知管理页面一个页面，作为系统通知的唯一管理与查看入口。页面采用"顶部操作栏 + 筛选栏 + 通知列表 + 底部分页"的经典管理后台布局，配合创建通知弹窗、通知详情弹窗与全局轻提示三类浮层完成全部交互。核心功能点如下：

编号功能点优先级能力说明
F-01 通知集中列表 P0 以表格形式集中展示全部通知，逐条呈现标题、内容摘要、来源、接收人员、状态、发送时间与创建时间，支持整行点击进入详情。
F-02 关键词检索 P0 按通知标题或通知内容进行模糊匹配，输入即时生效，不区分大小写，检索结果自动回到第一页。
F-03 来源与状态筛选 P1 提供来源（系统自动 / 管理员手动）与状态（已发送 / 待发送）两个下拉筛选，可与关键词检索叠加使用。
F-04 创建并发送全员通知 P0 管理员填写标题与内容后一键保存并发送，通知即时送达全体员工，创建人与创建时间由系统自动记录。
F-05 通知详情查看 P0 以弹窗形式展示单条通知的完整信息：标题、来源、状态、接收范围、创建人、创建时间、发送时间与保留换行的完整正文。
F-06 分页浏览 P1 底部常驻分页栏，展示总条数与当前区间，支持每页 10 / 20 / 50 / 100 条切换、上一页下一页与页码直达，页码过多时以省略号折叠。
F-07 空状态引导 P2 列表无数据时隐藏表格与分页栏，展示引导插画文案与"创建通知"快捷入口，指引用户完成首次发布。
F-08 系统通知清单说明 P2 顶部栏提供说明入口，展开后列出系统当前会自动推送的通知类型，帮助使用者了解消息来源。
F-09 操作结果反馈 P1 发送成功、校验失败等操作结果以全局轻提示统一反馈，区分成功与错误两种样式，短暂停留后自动消失。
💡 本期范围界定：接收范围固定为"全员"，通知创建后立即发送，不提供指定人员、定时发送、撤回与删除能力；通知列表为只读视图，除新建外不提供行级编辑操作。

1.3 核心概念定义

概念定义与说明
通知 系统内一条面向接收人发布的消息记录。一条通知包含：标题、内容、来源、接收范围、状态、创建人、创建时间与发送时间。通知一经发送即归档留存，可在列表中检索与查看详情。
通知来源 标识通知的产生方式，分两类：系统自动——由系统在业务节点触发自动推送，创建人记为"系统"；管理员手动——由管理员在通知管理页面主动创建发布，创建人记为实际操作人。两类来源在列表中以不同底色的标签区分。
通知状态 通知的发送生命周期状态，分两态：已发送——通知已送达接收人，为列表中的常态；待发送——通知已生成但尚未到达发送时点。本期管理员创建的通知在保存时即刻发送并置为"已发送"，因此手动发布不会产生待发送记录；待发送状态用于承接后续定时发送场景，筛选器已预留该选项。
接收人员 / 接收范围 通知的送达对象集合。本期接收范围固定为全员，即组织内全部在册成员。列表中按接收人数量呈现三种标识形态：全员、单人、多人（含"等 N 人"折叠）。
创建人 通知的责任主体。系统自动产生的通知，创建人显示为"系统"；管理员手动发布的通知，创建人显示为当前登录用户的姓名。创建人仅在通知详情中展示，列表不单列该字段。
创建时间 / 发送时间 创建时间为通知记录生成的时刻，保存时由系统自动写入，不可人工指定；发送时间为通知实际送达接收人的时刻。本期两者在保存发送时同时生成，取值一致；后续支持定时发送时，发送时间将体现为计划发送时点。
系统通知清单 系统当前会自动推送的通知类型集合，通过顶部栏说明入口对使用者公开。本期清单包含"技能审核通过"与"技能审核不通过"两类，随系统能力扩展而增补。

1.4 目标用户与典型场景

用户角色需求特征典型场景
系统管理员 负责全员管理类通知的发布与归档，关注发布是否成功、记录是否完整、历史是否可查。 行政管理员需要发布元旦放假安排：进入通知管理页面点击"创建通知"，填写标题与正文后保存并发送，系统提示"通知已发送"，新通知即刻出现在列表首位，创建人与创建时间自动留痕。
系统运维人员 关注系统自动产生的运行类消息，需要快速定位某个时间段的告警与维护通知。 运维人员排查一次夜间异常：在筛选栏将来源选为"系统自动"，并在搜索框输入"告警"，列表即时收敛到相关通知，点击行进入详情核对完整正文与发送时间。
部门管理者 需要确认本部门相关的会议、培训、任务类通知是否已下发，以及下发的具体内容。 部门经理收到员工询问培训时间：在搜索框输入培训名称关键词，找到对应通知后打开详情，将完整的开课时间与地点说明转达给员工。
普通使用者 被赋予查看权限时，关注与自己相关的历史通知，需要按状态与关键词快速找到目标消息。 员工想回看上个月发布的所有通知：将每页条数切换为 50 条，通过分页浏览完整历史，必要时用关键词缩小范围。
作为 系统管理员，我希望 在一个页面填写标题与内容就能把通知发给全体员工，以便 不必依赖邮件或群聊，且发布记录在系统内自动留痕。
作为 系统运维人员，我希望 按来源和关键词快速筛出系统自动推送的通知，以便 在排查问题时迅速定位相关的告警与维护记录。
作为 部门管理者，我希望 点开任意一条通知看到完整正文、创建人与发送时间，以便 向团队成员准确转达信息，并在有争议时有据可查。

二、功能架构与流程图

2.1 系统架构图

通知管理模块由一个页面与三类浮层构成。页面自上而下分为顶部栏（面包屑、通知说明入口、创建通知入口）、筛选栏（关键词检索 + 来源筛选 + 状态筛选）、通知列表（表格 / 空状态）与底部分页栏四层；浮层包含创建通知弹窗、通知详情弹窗与全局轻提示。数据主链路为：创建通知弹窗提交后写入通知数据，列表即时刷新并将新通知置于首位，详情弹窗按行读取单条通知的完整信息。

2.2 业务流程图

下图描述通知管理页面的核心业务流转，包含"发布通知"与"查阅通知"两条主线。管理员从顶部栏进入创建流程，填写标题与内容后提交；系统依次执行必填与长度校验，任一校验不通过则以错误轻提示阻断并停留在弹窗内，全部通过后写入通知数据、状态置为已发送、接收范围置为全员，列表刷新并将新通知置于首位。查阅主线中，使用者通过关键词与来源、状态筛选收敛结果，翻页浏览后点击任意行打开详情弹窗，查看完整正文与发布信息后关闭返回列表。

💡 业务闭环说明：发布主线以"校验通过 → 写入并发送 → 列表置顶 → 轻提示成功"闭环，校验失败不关闭弹窗、不产生脏数据，用户可在原弹窗内直接修正后重新提交；查阅主线以"筛选 → 分页 → 详情 → 关闭"闭环，详情弹窗为只读视图，关闭后列表的检索条件、筛选值与当前页码均保持不变。

三、详细设计

通知管理模块包含一个页面：通知管理页面。该页面为模块的唯一入口，承载通知的检索、浏览、创建与详情查看能力。以下按"页面 → 模块"两级组织，逐模块说明数据来源、显示规则、字段要求与交互行为。

🔹 3.1 通知管理页面

页面整体说明

页面采用固定高度全屏布局，自上而下分为三个区域：顶部栏（固定高度，不随内容滚动）、内容滚动区（承载筛选栏与通知列表，纵向独立滚动，滚动条为细窄样式）、底部分页栏（固定在页面底部，不随内容滚动）。页面加载完成后立即读取全部通知数据并按当前分页参数渲染列表。三类浮层（创建通知弹窗、通知详情弹窗、全局轻提示）以覆盖层形式叠加在页面之上，其中弹窗带半透明黑色遮罩，点击遮罩空白区域等同于取消关闭。

字段类型必填说明
页面标题 文本 是 浏览器标签页标题固定为"通知管理"；来源：模块名称，不随页面内操作变化。
页面布局 结构 是 顶部栏 + 内容滚动区 + 底部分页栏三段式；边界：整页禁止出现浏览器级滚动条，滚动只发生在内容区；内容区上下内边距为 24px。
弹窗遮罩 结构 — 创建通知弹窗与通知详情弹窗均带 40% 不透明度黑色遮罩，内容居中显示；交互：点击遮罩空白区域关闭弹窗，点击弹窗本体不关闭；效果：弹窗出现时带淡入与轻微上移动画。

3.1.1 顶部栏模块

该模块固定于页面顶部，展示当前页面在系统导航中的位置，并承载模块级的全局操作入口。模块内数据均来自当前登录态与模块配置，不随列表筛选变化。

字段类型必填说明
面包屑导航 文本 是 固定展示两级路径"系统管理 > 通知管理"，以右向箭头分隔；显示规则：一级"系统管理"为常规灰色文字，末级"通知管理"为深色加粗，标识当前位置；来源：系统菜单层级；边界：本页面为末级页面，末级不可点击。
通知说明按钮 按钮 是 紧邻面包屑末级右侧的圆形图标按钮，图标为信息符号，悬停提示文案"系统通知说明"；显示规则：浅靛蓝底 + 靛蓝图标，尺寸 28×28px；交互：点击展开 / 收起通知说明面板；边界：点击按钮本身不会冒泡触发页面级的面板关闭逻辑。
创建通知按钮 按钮 是 位于顶部栏最右侧，蓝色实心按钮，图标为加号 + 文案"创建通知"；交互：点击打开创建通知弹窗，弹窗内表单全部重置为初始空值；显示规则：悬停时底色加深；边界：在通知列表任意筛选结果下均可见可用，包括列表为空时。
顶部栏高度 结构 — 固定 64px，白底 + 底部 1px 分隔线；边界：不参与内容区滚动，始终吸顶可见。

3.1.2 通知说明面板模块

该模块为顶部栏通知说明按钮的展开浮层，用于向使用者公开系统当前会自动推送的通知类型清单。清单内容由模块统一维护，与通知列表数据相互独立。

字段类型必填说明
面板标题 文本 是 固定文案"系统通知清单"；显示规则：13px 加粗深灰，位于面板顶部，与下方列表以 10px 间距分隔。
清单项 列表 是 逐条列出系统会自动推送的通知类型，每项前置一个状态图标；本期清单固定两项："技能审核通过"（前置对勾圆圈图标）、"技能审核不通过"（前置叉号圆圈图标）；显示规则：13px 灰色文字，图标为靛蓝色，单项上下内边距 5px；来源：模块维护的通知类型清单；边界：清单随系统能力扩展增补，无数据时不展示面板内容。
面板定位 结构 — 相对于说明按钮水平居中、向下偏移 8px 展开，顶部带指向按钮的小三角；边界：最小宽度 240px，层级高于页面内容，不被列表遮挡。
展开 / 收起状态 交互 — 触发：点击通知说明按钮切换展开与收起；显示规则：收起状态下面板完全透明且不响应鼠标事件，展开状态下带 0.15 秒淡入与位移动画；交互：点击面板与按钮以外的页面任意区域自动收起；边界：面板为纯展示内容，不可选中其中文字执行操作。

3.1.3 筛选模块

该模块位于内容区顶部，提供通知列表的检索与筛选能力。三个筛选条件为"与"关系，可任意组合叠加使用；筛选作用于全部通知数据，任一条件变化都会立即重新计算结果集。

字段类型必填说明
搜索关键词 单行文本 否 占位提示"搜索通知标题或内容..."，输入框左侧内嵌放大镜图标；匹配规则：对通知标题与通知内容做模糊匹配，命中任一即保留该条；边界：不区分大小写，输入值首尾空格自动忽略；为空表示不按关键词过滤；交互：输入即时生效（无需点击搜索按钮）；效果：条件变化后列表回到第一页并重新渲染，无匹配结果时展示空状态。
来源筛选 下拉单选 否 可选值：全部来源（默认）/ 系统自动 / 管理员手动；显示规则：右侧内嵌下拉箭头图标，箭头不响应点击（点击穿透至下拉框）；匹配规则：选择非"全部来源"时，仅保留来源完全相等的通知；交互：选择后立即生效并回到第一页。
状态筛选 下拉单选 否 可选值：全部状态（默认）/ 已发送 / 待发送；匹配规则：选择非"全部状态"时，仅保留状态完全相等的通知；交互：选择后立即生效并回到第一页；边界：本期通知创建后即刻发送，实际数据均为已发送，选择"待发送"通常返回空结果并展示空状态，该选项为后续定时发送能力预留。
筛选栏布局 结构 — 搜索框占据左侧弹性宽度且最大不超过 448px，两个下拉框成组靠右排列；边界：窄屏下允许换行，行间距 8px；筛选栏与下方列表间距 24px。
输入框聚焦态 交互 — 搜索框与下拉框获得焦点时，边框变为蓝色并叠加 2px 蓝色半透明外发光；效果：聚焦态与默认态切换带 0.15 秒过渡动画。
💡 筛选与分页的联动规则：关键词、来源、状态任一条件变化时，当前页码强制重置为第 1 页，避免出现"筛选后停留在越界页码导致列表空白"的问题；每页条数不受筛选影响，保持用户上次的选择。

3.1.4 通知列表模块

该表格展示系统内全部通知记录，数据来源为通知数据集，并按筛选模块的条件实时过滤、按分页模块的参数切片展示。列表为只读视图，除跳转详情外不提供行级编辑操作。

列表字段说明

字段类型必填说明
标题 文本 + 图标 是 列最小宽度 170px。前置一个来源图标：系统自动的通知显示机器人图标（靛蓝色），管理员手动的通知显示铃铛图标（蓝色）。标题文字加粗深色，悬停整行时转为蓝色；显示规则：单行展示，最大宽度 190px，超出以省略号截断；边界：鼠标悬停时通过浮层提示展示完整标题；来源：创建通知时用户填写，或系统按业务节点自动生成。
内容 文本 是 列最小宽度 220px。展示通知正文摘要，灰色常规字重；显示规则：单行展示，最大宽度 230px，超出以省略号截断，正文中的换行统一替换为空格后展示；边界：鼠标悬停时通过浮层提示展示完整正文（含原始换行）；来源：通知正文原文。
来源 标签 是 以圆角胶囊标签展示，取值二选一：系统自动（浅靛蓝底 + 靛蓝字）、管理员手动（浅蓝底 + 蓝字）；显示规则：12px 中等字重，标签不换行；来源：通知的产生方式，系统写入不可修改。
接收人员 标签 是 以带图标的胶囊标识展示接收范围，最大宽度 200px，按接收人数量呈现三种形态：
① 全员——群组图标 + 文案"全员"，浅靛蓝底靛蓝字，悬停提示"全员通知（N 人）"，N 为组织在册成员总数；
② 单人——单人图标 + 该成员姓名，浅灰底灰字，悬停提示"单独发送给 某成员"；
③ 多人——多人图标 + "前两位成员姓名、等 N 人"（恰好两人时不追加"等 N 人"），浅灰底灰字，悬停提示"指定人员："后接全部成员姓名以顿号分隔；
显示规则：文案过长时以省略号截断，图标不被压缩；边界：管理员手动创建的通知接收范围恒为全员。
状态 标签 是 以圆角胶囊标签展示，取值二选一：已发送（浅绿底 + 绿字）、待发送（浅黄底 + 橙字）；来源：通知发送生命周期，保存发送后自动置为已发送。
发送时间 日期时间 是 格式 YYYY-MM-DD HH:mm，不换行展示；显示规则：已发送的通知为常规灰色，待发送的通知以橙色展示（表示该时间为计划发送时点）；边界：无发送时间时展示长破折号"—"占位；来源：通知实际送达时刻，本期与创建时间同时生成。
创建时间 日期时间 是 格式 YYYY-MM-DD HH:mm，不换行展示，灰色常规字重；来源：通知记录生成时刻，保存时由系统自动写入，精确到分钟（秒位不展示）；边界：不可人工指定或修改。
操作 文字链接 是 列内容右对齐，本期仅提供一个链接：查看（蓝色文字，悬停加深）；交互：点击打开该条通知的详情弹窗；边界：点击链接不会重复触发行点击（链接已阻断事件冒泡），二者最终行为一致。
整行点击 交互 — 触发：点击数据行任意非链接区域；行为：打开该条通知的详情弹窗；显示规则：整行鼠标指针为手型，悬停时行背景变为浅灰；边界：表头行不响应点击。
表头 结构 — 固定八列：标题 / 内容 / 来源 / 接收人员 / 状态 / 发送时间 / 创建时间 / 操作；显示规则：浅灰底、12px 大写字距加宽的灰色加粗文字，底部 1px 分隔线；边界：本期不支持点击表头排序。
行分隔与容器 结构 — 数据行之间以极浅灰色 1px 底线分隔，行内单元格上下内边距 12px、左右 16px；外层容器为白底、12px 圆角、1px 浅灰描边且内容溢出裁切；边界：表格宽度撑满容器，横向不出现滚动条（依靠列内截断控制宽度）。
排序规则 规则 — 默认按通知记录的产生顺序倒序展示，最新创建或最新发送的通知排在最前；效果：新发布的通知保存后立即出现在第一页首行。

3.1.5 空状态模块

该模块在通知列表没有任何可展示数据时替代表格出现，用于避免页面出现大面积空白，并直接把用户引导到"创建通知"这一核心动作上。空状态既覆盖"系统内尚无任何通知"的首次使用场景，也覆盖"筛选条件过严导致无匹配结果"的场景。

字段类型必填说明
空状态图标 图标 是 居中展示铃铛轮廓图标，超大字号（60px 级）、极浅灰色；作用：以图形化方式弱化"无数据"的负面感受。
主文案 文本 是 固定文案"暂无通知"；显示规则：18px 中灰色，位于图标下方 16px 处。
辅助文案 文本 是 固定文案"点击「创建通知」向人员发送通知"；显示规则：14px 浅灰色，位于主文案下方 8px 处，与下方按钮间距 24px；作用：明确告知下一步操作路径。
创建通知按钮 按钮 是 蓝色实心按钮，文案"创建通知"，左右内边距 24px；交互：点击打开创建通知弹窗，行为与顶部栏创建按钮完全一致；显示规则：悬停底色加深。
显示条件 规则 — 触发：经筛选后的通知总数为 0；行为：隐藏通知表格容器，展示空状态模块，同时隐藏底部分页栏；边界：一旦总数大于 0（例如用户清空搜索关键词），立即恢复表格并隐藏空状态。
布局 结构 — 纵向居中排列，整体上下内边距 80px，全部元素水平居中对齐。

3.1.6 分页模块

该模块固定于页面底部，展示当前筛选结果的分页统计信息并提供翻页控制。分页统计基于筛选后的结果集实时计算，页长变化或筛选条件变化时同步刷新。

字段类型必填说明
总条数 数值 是 文案格式"共 N 条"，N 为筛选后命中的通知总数；显示规则：数字加粗深色，其余为灰色 13px 说明文字；来源：筛选结果集实时统计。
当前区间 文本 是 文案格式"第 X-Y 条"，X 为当前页首条在结果集中的序号，Y 为当前页末条序号；边界：Y 不超过总条数（末页按实际条数收口）；总数为 0 时展示"第 1-0 条"，但此时整个分页栏已隐藏。
每页条数 下拉单选 是 文案"每页 [N] 条"，可选值 10（默认）/ 20 / 50 / 100；交互：切换后立即按新页长重新分页，并强制回到第 1 页；边界：页长选择在同一页面会话内保持，不随筛选条件变化而重置；显示规则：下拉框获焦时边框转为靛蓝色。
上一页按钮 按钮 是 方形图标按钮（30×30px），图标为左向箭头，无障碍标签"上一页"；交互：点击跳转至前一页并重新渲染列表；边界：当前处于第 1 页时按钮禁用（透明度降至 40%，指针为禁止态，点击无效）。
页码列表 按钮组 是 逐个展示可跳转页码，点击直达对应页；显示规则：当前页为靛蓝底白字并带同色描边，其余页码为灰色文字、悬停浅灰底；折叠规则：总页数不超过 7 页时全部展示；超过 7 页时固定展示首页与末页，中间仅展示当前页及其前后各一页，被折叠的位置以省略号"…"占位（省略号不可点击）；边界：仅 1 页时展示单个高亮页码"1"。
下一页按钮 按钮 是 方形图标按钮（30×30px），图标为右向箭头，无障碍标签"下一页"；交互：点击跳转至后一页并重新渲染列表；边界：当前处于末页时按钮禁用（透明度降至 40%，指针为禁止态，点击无效）。
越界保护 规则 — 触发：请求跳转的页码小于 1 或大于总页数；行为：忽略该次跳转，保持当前页不变；补充：当筛选导致总页数减少、当前页码超出范围时，自动收敛到最后一个有效页再渲染。
分页栏显隐 规则 — 触发：筛选后的通知总数为 0；行为：整个分页栏隐藏，同时展示空状态模块；总数大于 0 时恢复展示。
分页栏布局 结构 — 白底 + 顶部 1px 分隔线，左右内边距 32px；左侧为统计信息组（总条数 | 当前区间 | 每页条数，以竖线分隔），右侧为翻页控制组（上一页 + 页码 + 下一页）；边界：固定在页面底部，不参与内容区滚动。

3.1.7 创建通知弹窗模块

该模块为管理员发布全员通知的表单浮层，由顶部栏"创建通知"按钮或空状态"创建通知"按钮触发。弹窗打开时表单全部重置为初始状态：标题与内容清空、字数计数归零、接收人员恢复为默认的"全员"、创建时间预览刷新为当前时刻。弹窗内容区可独立纵向滚动，标题栏与底部按钮栏吸顶吸底常驻。

表单字段说明

字段类型必填说明
通知标题 单行文本 是 占位提示"请输入通知标题"，标签右侧带红色星号标识必填；来源：用户输入；边界：最多 50 个字符，达到上限后无法继续输入；字数计数：输入框下方展示"当前字数/50"，默认灰色，超过 40 字符转为橙色警示；校验：去除首尾空格后为空时阻止提交，并以错误轻提示"请输入通知标题"，弹窗保持打开、已填内容不丢失。
通知内容 多行文本 是 占位提示"请输入通知内容..."，默认 5 行高度且不允许用户拖拽改变尺寸，标签右侧带红色星号；来源：用户输入；边界：最多 500 个字符，达到上限后无法继续输入，支持换行输入且换行在详情中按原样保留；字数计数：输入框下方展示"当前字数/500"，默认灰色，超过 450 字符转为橙色警示；校验：① 去除首尾空格后为空时提示"请输入通知内容"；② 长度超过 500 字符时提示"通知内容不能超过 500 字符"（作为提交兜底校验）；两种情况均阻止提交并停留在弹窗内。
接收人员 单选 是 标签右侧带红色星号；本期仅提供"全员"单一选项且默认选中，通知将送达组织内全部在册成员；显示规则：单选项前置圆形单选控件，选中态为蓝色；边界：因仅有单一选项，用户无需也无法切换到其他接收范围，指定人员发送为后续迭代能力；提交时接收范围固定写入"全员"。
创建时间（只读提示） 说明区 — 浅灰底信息条，左侧为时钟图标 + 文案"创建时间（保存时自动生成）"，右侧展示按当前时刻刷新的时间预览（格式 YYYY-MM-DD HH:mm）；作用：在提交前明确告知用户记录将采用的时间口径；边界：仅作展示不收集输入，用户不可修改；实际写入的创建时间以点击保存的时刻为准，可能与预览存在分钟级差异。
弹窗标题 文本 是 固定文案"创建通知"，18px 加粗深色；显示规则：位于吸顶标题栏左侧，右侧为关闭图标按钮。
关闭按钮 按钮 — 标题栏右侧的叉号图标按钮；交互：点击关闭弹窗并放弃本次填写，不做任何保存；显示规则：悬停时底色变为浅灰、图标为灰色。
取消（按钮） 按钮 — 底部按钮栏左侧，白底灰字带浅灰描边；交互：点击关闭弹窗，放弃本次填写的全部输入，不产生任何通知记录；显示规则：悬停底色转为浅灰。
保存并发送（按钮） 按钮 — 底部按钮栏右侧，蓝色实心按钮；交互：点击后依次执行必填与长度校验，全部通过则写入通知记录——来源记为"管理员手动"、状态置为"已发送"、接收范围置为"全员"、创建人记为当前登录用户、创建时间与发送时间取提交时刻（精确到分钟），随后关闭弹窗、列表回到第一页并刷新，新通知出现在列表首行，同时以成功轻提示"通知已发送"反馈；校验不通过时不关闭弹窗、不写入数据；显示规则：悬停底色加深。
弹窗尺寸与滚动 结构 — 宽度自适应且最大 672px，左右外边距 16px，最大高度为视口的 90%，超出时内容区纵向滚动并采用细窄滚动条样式；边界：标题栏与底部按钮栏在滚动时保持吸附可见；弹窗出现带淡入动画，圆角 16px 并带深投影。
💡 校验顺序与反馈约定：提交时按"标题必填 → 内容必填 → 内容长度"顺序校验，命中第一条即中断并给出对应的错误轻提示，不累积展示多条错误；所有校验失败均保持弹窗打开并保留用户已填写的内容，避免误操作导致输入丢失。

3.1.8 通知详情弹窗模块

该模块为单条通知的只读详情浮层，由列表数据行点击或行内"查看"链接触发。弹窗打开时按被点击的通知记录读取其完整信息并渲染，数据与列表行完全一致。本期详情不提供接收人明细、已读统计与任何编辑或撤回操作。

字段类型必填说明
通知图标 图标 是 头部左侧 48×48px 圆角图标块，内置铃铛图标，蓝色系；背景为从浅蓝到浅靛蓝的对角渐变；作用：作为详情弹窗的视觉锚点，不承载业务含义。
通知标题 文本 是 18px 加粗深色，展示完整标题；显示规则：单行展示，过长时以省略号截断且不挤压右侧标签与关闭按钮；来源：通知记录的标题原文。
来源标签 标签 是 紧随标题右侧，取值与列表一致：系统自动（浅靛蓝底靛蓝字）/ 管理员手动（浅蓝底蓝字）；显示规则：与状态标签水平并排，空间不足时允许换行到下一行。
状态标签 标签 是 紧随来源标签右侧，取值与列表一致：已发送（浅绿底绿字）/ 待发送（浅黄底橙字）。
接收人员 标签 是 位于标题行下方，前置说明文字"接收人员："，其后展示与列表规则完全一致的接收范围标识（全员 / 单人 / 多人三种形态及对应悬停提示）；来源：通知记录的接收范围与接收人集合。
创建人 文本 是 位于元信息行，前置人物轮廓图标与文字"创建人："；显示规则：系统自动产生的通知展示"系统"，管理员手动发布的通知展示操作人姓名；来源：通知记录的责任主体；边界：仅在详情中展示，列表不单列该字段。
创建时间 日期时间 是 位于元信息行，前置时钟图标与文字"创建时间："，格式 YYYY-MM-DD HH:mm；来源：通知记录生成时刻。
发送时间 日期时间 是 位于元信息行，前置发送图标与文字"发送时间："；显示规则：已发送的通知直接展示时间值；待发送的通知在时间值前追加"计划"二字，表示该时间为计划发送时点；边界：无发送时间时展示长破折号"—"占位。
元信息行布局 结构 — 创建人、创建时间、发送时间三项以 12px 浅灰色文字横向排列，项间距 16px；边界：窄屏下允许换行；与下方内容卡片间距 20px。
通知内容 多行文本 是 置于浅灰底圆角卡片内，卡片顶部为带正文图标的分区标题"通知内容"；显示规则：14px 深灰文字、宽松行高，完整展示正文且保留原始换行（换行按原样折行呈现，不做单行截断）；边界：卡片内容随正文长度自然撑高，超出弹窗最大高度时由弹窗整体滚动；来源：通知记录的正文原文。
关闭按钮 按钮 — 头部右侧 32×32px 叉号图标按钮；交互：点击关闭详情弹窗返回列表；显示规则：默认灰色，悬停时图标加深且底色转为浅灰。
底部关闭按钮 按钮 — 底部按钮栏右对齐，白底灰字带浅灰描边，文案"关闭"；交互：与头部关闭按钮行为一致，关闭弹窗返回列表；边界：本期底部仅提供关闭操作，无编辑、撤回、删除等按钮。
关闭方式汇总 交互 — 三种关闭途径：① 点击头部关闭按钮；② 点击底部"关闭"按钮；③ 点击弹窗外的遮罩空白区域。三者效果一致，关闭后列表的检索关键词、筛选值、当前页码与每页条数均保持不变。
弹窗尺寸与滚动 结构 — 宽度为视口的 90% 且最大 760px，最大高度为视口的 85%，内容超出时弹窗内部纵向滚动；圆角 16px、深投影；效果：出现时带 0.2 秒遮罩淡入与 0.25 秒内容上移动画；层级高于页面全部内容与创建通知弹窗以外的浮层。

3.1.9 全局轻提示模块

该模块为跨模块复用的操作结果反馈组件，用于在不打断用户当前操作的前提下告知一次动作的结果。所有成功与失败反馈统一走该组件，不使用浏览器原生弹窗。

字段类型必填说明
提示文案 文本 是 一句话说明操作结果，14px 中等字重；本期文案清单：
成功类——"通知已发送"；
错误类——"请输入通知标题"、"请输入通知内容"、"通知内容不能超过 500 字符"；
边界：文案由触发方指定，单条提示仅承载一条信息，不堆叠多行。
提示类型 枚举 是 取值二选一，决定提示的视觉样式：成功——浅绿底 + 绿字 + 浅绿描边；错误——浅红底 + 红字 + 浅红描边；显示规则：两种类型均为 10px 圆角并带明显投影，便于在任意背景上识别。
展示位置 结构 — 固定在视口水平居中、距顶部约 10% 高度处；层级高于所有弹窗与遮罩，确保在弹窗之上依然可见；边界：不随页面内容滚动。
展示时长 规则 — 出现后停留 2.5 秒自动消失；效果：出现时带 0.25 秒淡入动画；边界：无需用户手动关闭，不可点击交互。
并发与覆盖 规则 — 同一时刻仅展示一条提示；触发：新提示到来时直接覆盖当前提示的文案与样式，并重新开始 2.5 秒计时；边界：不排队、不堆叠，避免多条提示遮挡页面。
