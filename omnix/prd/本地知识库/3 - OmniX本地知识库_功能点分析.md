# OmniX 本地知识库 · PRD 功能点分析

**核心闭环**：本地目录 → 写入链（页面 + 片段 + 图谱 + 时间线）→ 搜索链（混合检索 + 引用回答）→ 持续增量维护  
**三条产品原则**：本地优先 · 可追溯 · 不编造

---

## 一、知识库与资料源管理

> 把"用户本地目录"登记为可管理的知识库实例，并约定资料源边界。

| 功能点 | 说明 |
| --- | --- |
| 创建知识库 | 用户输入名称并绑定一个本地文件夹绝对路径，系统创建知识库实例 |
| 多知识库实例 | 支持同时存在多套知识库数据，按"知识库实例 + 资料源"两层轴组织 |
| 资料源注册 | 绑定目录自动登记为"默认资料源根目录"，界面只展示这一条绑定关系 |
| 重新绑定目录 | 用户修改目录位置必须显式重新绑定，系统不得静默改扫其他目录 |
| 目录权限校验 | 校验目录存在、可读、路径可规范化；失败则不创建半成品知识库 |
| 扩展：多资料源 / 多用户 | 后续支持多资料源、小团队共享、外部智能体接入场景 |

---

## 二、写入链（资料导入与知识化）

> 把本地文件从"原文件"转为"可搜索、可提问、可追溯"的页面体系，分八节点推进。

| 功能点 | 说明 |
| --- | --- |
| 文件夹绑定导入 | 仅支持"选文件夹绑定"入口，不提供逐文件上传 / 手工粘贴入口 |
| 首次全量扫描 | 客户端首次全量扫描绑定目录，形成初始文件清单 |
| 持续监听 / 增量扫描 | 之后持续监听或增量扫描发现变更（目录监听在 V1.1 补齐） |
| 变更识别 | 依据路径、文件状态、内容哈希识别新增 / 修改 / 重命名 / 删除 / 无变化 |
| 文件路由 | Markdown 直连解析；代码按同步策略；PDF/Word/Excel/PPT 路由 MinerU |
| 不支持 / 失败处理 | 无解析器文件标记"暂不支持 / 等待解析"，不得伪装为已知识化 |
| 解析器 / 噪声隔离 | 高置信度噪声内容隔离并排除检索；失败保留待修复记录 |
| 标准化内部 Markdown | 统一标题/正文/元数据/时间/来源定位；PDF 留页码、PPT 留幻灯片、Excel 留工作表 |
| 原文件零改动 ★核心 | 原文件始终留在绑定目录，不移动、不改写、不生成解析副本 |
| 完整页面建立 | 持久化正文、frontmatter、时间线、页面标识，作为可完整阅读的读模型 |
| Compiled Truth 生成 | 证据充分时形成"当前最佳理解"；无回溯证据不得写入 Compiled Truth |
| 内容切分为片段 | 按段落/语义边界生成带页内位置与来源定位的 content_chunks |
| 关键词索引 | 片段原文进入关键词（全文）索引，不依赖嵌入服务，必须始终可用 |
| 向量化（可选） | 按配置生成向量；不可用时标记"向量待完成"而非报告完全可用 |
| 知识图谱补建 | 页面/实体为节点，带类型、可回原文的链接为边，提供关系证据 |
| 标签 / 别名 / 时间证据 | 从 frontmatter、链接、时间信息写入对应索引，增强检索排序 |
| 同步收敛与幂等 | 对增改删重做幂等收敛、软删除、回填安排，返回批次级状态 |
| 失败重试 / 定向回填 | 可重试失败项、仅执行回填，不必重做整个目录 |
| 解析器版本重建 | 解析器升级或源文件变化后，据哈希与版本重新解析 |

## 三、写入状态机（进度可见性）

> 强制区分八个状态，用可解释的最终状态替代模糊的"导入成功"。

| 状态 | 含义 | 用户可做什么 | 不可误导为 |
| --- | --- | --- | --- |
| 待扫描 | 已绑定，尚未形成本轮文件清单 | 等待扫描或手动刷新 | 已导入 |
| 待解析 | 已进入清单，尚未形成标准页面 | 查看进度 | 可搜索 |
| 等待解析器 / 暂不支持 | 无对应解析器，等待能力接入 | 查看文件类型和原因，等待或忽略 | 已知识化、可问答 |
| 页面已写入 | 页面与来源凭据已持久化 | 查看来源定位，编辑原文件 | 已完成全部索引 |
| 关键词可检索 | 已切分，可做全文 / 关键词召回 | 搜索明确名称和词组 | 语义检索已可用 |
| 向量待完成 | 页面存在但尚未嵌入 | 等待 / 执行回填 | 完全可用 |
| 完全可用 | 页面/关键词/向量就绪，可问答追溯 | 自然语言搜索、问答、追溯 | 永远无需维护 |
| 已隔离 / 待修复 | 质量或解析问题要求处理 | 查看原因、修复、重试或放行 | 正常参与检索 |

## 四、搜索链（检索与回答）

> 以"关键词 + 语义 + 知识图谱 + 时间证据"为混合检索基础，拆分为检索层与回答层。

| 功能点 | 说明 |
| --- | --- |
| 范围与权限前置 ★核心 | 检索前锁定知识库、资料范围、外部调用方权限 |
| 多入口路由 | 直达页面 / 快速搜索 / 混合检索 / 回答，按用户意图分流 |
| 意图识别 | 识别实体、关系、事件、时间、一般问题，确定检索深度与时间偏好 |
| 多查询扩展 | 扩展为等价表达，原问题必保留；扩展失败仅用原问题 |
| 语义向量召回 | 在 content_chunks 按相似度召回，每页仅保留最强片段 |
| 关键词召回 ★核心 | 全文索引匹配名称/术语/文件线索/精确短语，必须始终可用 |
| 知识图谱召回 | 关系问题沿带类型边有限跳数遍历，返回路径证据，不得猜测关系 |
| 时间证据召回 | 关系/时间问题补充时间线与时间范围，不淹没近期事件 |
| RRF 融合 ★核心 | 互惠排名融合合并多路候选，不直接相加不同算法原始分数 |
| Compiled Truth 权重 | 权威页面受限提升（时间/事件问题关闭或降低该提升） |
| Backlink 图谱权重 | 按被其他可信页面引用程度温和提升连接度 |
| 来源质量权重 | 目录策略对高价值/低信号资料排序调整，可配置可审计 |
| 多层去重 | 限制同页片段数、删除相似片段、保页面类型多样性 |
| 重排与上下文裁剪 | 启用重排器时交叉编码重排，按预算裁剪证据数量 |
| 回答与引用 ★核心 | 读完整页面后生成结论、引用、冲突、信息缺口，不编造 |
| 语义缓存 | 同范围/同嵌入空间/同检索配置直接返回证据包，故障不阻断 |
| 降级机制 ★核心 | 嵌入不可用→仅关键词+图谱；增强失败→回退候选；缓存不跨源复用 |
| 三类空结果区分 ★核心 | 无权限=拒绝、无命中=未找到、证据不足=无法确认，三者不混 |
| 搜索输出契约 | 结果含标题/片段/匹配理由/命中路径/来源定位/图谱时间证据/降级说明 |

## 五、隔离与权限（安全边界）

> 多库、多源或外部接入场景下，保证查询、写入、可见范围受约束，避免串库越权。

| 功能点 | 说明 |
| --- | --- |
| 单用户默认无显式权限 | 单用户场景默认无显式权限管理，降低上手门槛 |
| 多库 / 多源隔离 ★核心 | 查询、写入、可见范围同时受知识库与资料源两层约束，避免串库越权 |
| 智能体授权访问 | 智能体只能访问被授权的知识库和资料源 |
| 外部调用方权限校验 | 检索前置校验外部调用方权限，无权限返回拒绝 |

---

## 六、维护与持续运营

> 让知识库随时间累积而非重复构建，健康状态持续暴露。

| 功能点 | 说明 |
| --- | --- |
| 增量同步 | 绑定后新资料自动进入已有知识体系，不每次重建 |
| 健康状态暴露 | 资料源仍有失败/隔离/未嵌入时持续暴露健康状态，不容忍"扫描完成=可用" |
| 向量失效与回填 | 更换嵌入模型/维度后旧向量失效并回填，不混用向量空间 |
| 异步质量记录 | 记录缓存命中、召回臂启用、耗时、降级原因用于评估，不改当前回答 |
| 夜间维护 | 补强自动维护、冲突整理，建立在 V1 追溯链之上 |

## 七、体验与界面

> 产品语言面向普通用户，但复杂步骤全部可见，可回到原文核验。

| 功能点 | 说明 |
| --- | --- |
| 清晰主路径 | 创建库 → 绑定文件夹 → 等待同步 → 搜索 / 提问，主路径一目了然 |
| 不强迫理解底层概念 | 普通用户不需懂 Markdown/向量/RRF/资料源即可开始使用 |
| 失败原因与状态可见 | 用户可看文件状态、失败原因、来源定位，不只有"黑盒处理中" |
| 返回原文件入口 | 页面、搜索结果、答案均提供回到原文件入口，始终知道资料处理到哪一步 |
| 本地优先 ★核心 | 默认数据落在用户机器或受控数据库，非强依赖云托管 |
